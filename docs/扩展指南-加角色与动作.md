# DeskPet 扩展指南：加角色 & 加动作（免写代码版）

> 适用对象：美术 / 非程序员。目标是在**不碰任何 `.ts` 源码**的前提下，新增一个角色、或给已有角色加动作。
> 所有改动都是「放文件 + 改 JSON」。改完保存即生效（开发模式 `npm run dev` 下按 **Ctrl+R** 重载；便携版重开 `DeskPet.exe`）。

---

## 0. 一句话理念

DeskPet = **框架（引擎，已写好）+ 数据填充（你写的 JSON + PNG）**。

- 一个**角色** = 一组数据文件（`assets/<id>/` + 3 份 JSON）
- 一个**动作** = `actions/<id>.json` 里的一条数据

只要你的新动作能套进下面 7 种「运行模式」之一，它就**纯数据、零代码**。只有当你要一种全新的运动方式（现有 7 种都装不下）时，才需要改引擎代码。

---

## 1. 文件地图

每个角色由这些文件组成（`<id>` 是角色英文名，如 `nina`）：

| 文件 | 作用 | 必填 |
|---|---|---|
| `assets/<id>/*.png` | 美术帧（一张图 = 一帧动画） | ✅ |
| `config/characters/<id>.json` | 角色基础属性（尺寸/速度/默认动作等） | ✅ |
| `config/actions/<id>.json` | 该角色的全部动作清单 | ✅ |
| `config/config.json` | 全局清单，**角色 id 要在这里登记一行** | ✅（注册） |

> 帧名 ↔ PNG 的映射在 `config/images/<id>.json`（`{ "shime1": "shime1.png", ... }`）。换皮时改这个映射即可，不用动动作配置。

---

## 2. 加一个新角色（4 步）

### ① 放美术
把帧图放进 `assets/<id>/`，例如 `assets/momo/idle1.png`、`assets/momo/walk1.png` …

### ② 写 `config/characters/<id>.json`（最小模板）
```json
{
  "name": "桃子",
  "size": { "width": 150, "height": 150 },
  "moveSpeed": 1.5,
  "bottomMargin": 0,
  "interactionDuration": 3500,
  "facing": "left",
  "defaultAction": "idle",
  "walkAction": "walk",
  "climbAction": "climb",
  "flyAction": "fly",
  "dragAction": "drag",
  "fallAction": "fall"
}
```
> `size.height` 建议设成**美术源图的原始高度**（四周透明留白由美术自己处理），否则角色会显得被压扁。
> 想让攀爬手感不同：`climbMaxMs`(一次攀爬多久下墙，默认 20000) / `climbTurnChance`(中段折返概率，默认 0.35) /
> `climbEndFlyChance`(到期起飞而非掉落的概率，默认 0.5) / `climbCooldownMs`(下墙后冷却，默认 3000) / `climbDownAction`(专用下爬动作，可选)。

### ③ 写 `config/actions/<id>.json`（最小模板，至少含 idle + walk）
```json
{
  "actions": {
    "idle":  { "behavior": "static", "frames": ["idle1", "idle2", "idle3"], "frameMs": 1000, "loopCount": 1 },
    "walk":  { "behavior": "walk",   "frames": ["walk1", "walk2", "walk3", "walk4"], "frameMs": 500, "loop": true },
    "drag":  { "behavior": "drag",   "frames": ["idle1"], "loop": true }
  }
}
```

### ④ 在 `config/config.json` 登记 id（一行）
```json
{
  "characters": ["nina", "rose", "rebeza", "momo"]
}
```
把你的 `<id>` 加进这个数组。**不登记 = 程序不加载该角色。**

### ⑤（可选）轻触对话 `config/characters/<id>.json`
```json
{ "tapDialogue": ["今天也要加油！", "嘿嘿~"] }
```
轻触（点击不拖动）角色时随机说一句；省略则轻触安静。

完成 → 重开程序，托盘「管理面板」里就能看到新角色，点「召唤」。

## 3. 给角色加一个动作

直接在 `config/actions/<id>.json` 的 `actions` 里加一条。

### 字段速查表

| 字段 | 含义 | 默认 |
|---|---|---|
| `behavior` | 运行模式（见下表，**7 选 1**） | 必填 |
| `frames` | 帧名数组；也可写成 `{ "name": "x", "ms": 120, "vx": 3, "vy": 0 }` 做逐帧独立时长/位移 | 必填 |
| `frameMs` | **动作级**统一每帧时长(ms)，推荐 200~2000（越大越慢） | — |
| `speed` | 旧字段：帧率系数，实际 fps = `speed × 60`。已被 `frameMs` 取代，仅向后兼容 | 0.1 |
| `loop` | 是否循环（`false` = 播一遍停在末帧，如摔倒） | true |
| `loopCount` | 循环轮数；`loop:true` 的动作**必须**靠它或 `durationMs` 才能结束 | — |
| `durationMs` | 动作限时(ms)；`0` = 由外部事件/动画自身收尾（不挂定时器） | — |
| `menu` | `true` 时出现在右键动作菜单 | false |
| `dialogue` | 触发时显示的台词（数组随机取一句） | — |
| `moveSpeed` | 该动作自己的位移速度（覆盖角色级） | — |
| `next` | 播完接续的动作（见 §3.4） | — |
| `trackMouse` | `static` 动作期间自动朝鼠标翻转 | — |
| `windowMode` | `"carry"` 搬窗口走 / `"ledge"` 挂窗沿 | — |
| `offset` | 该动作 body 相对容器的显示偏移（倒挂帧用） | — |
| `width` / `height` | 该动作的**显示尺寸上限**（覆盖角色 `size`，宽帧/飞帧用）。⚠ 显示尺寸 = **鼠标命中框**（见 §3.6） | 角色 `size` |

### 3.1 七种运行模式（`behavior`）何时用

| behavior | 说明 | 典型动作 |
|---|---|---|
| `static` | 原地待机/播放 | 站、坐、睡、祈祷、摔倒 |
| `walk` | 沿地面左右走 | 走、跑、爬(地)、`creep`（蹑手蹑脚） |
| `climb` | 沿屏幕左右边框爬。**一次会话内上下折返巡逻**，到 `climbMaxMs`(默认 20s) 才下墙（按 `climbEndFlyChance` 起飞，否则掉落）；上下共用同一套帧 | 爬墙 |
| `drag` | 鼠标拖拽 | 被拖 |
| `ceiling` | 贴天花板横向爬（倒挂） | 天花板爬行 |
| `chase` | 追鼠标指针（水平跑向指针 x） | 追光标 |
| `fly` | 屏幕内 2D 自由飞行（不受重力/地面约束） | 飞行 |

> 逐帧还可带 `vx` / `vy`（px/帧@60fps）：`walk` 类用 `vx`、`climb` 类用 `vy`，写 `0` = 该帧原地不动（踩步/握稳的支撑帧）。

> 两个**行为无关**开关能再扩种类、不必加新 behavior：
> - `trackMouse: true` —— 静止时头/身朝向鼠标（对应「看向鼠标」类）
> - `windowMode: "carry" | "ledge"` —— 搬窗口 / 挂窗口边缘（需 Windows 真机，依赖内置 koffi）

### 3.2 逐帧独立时长（修复变速动画）
普通写法所有帧同速；要变速（如蹑手蹑脚先快后慢）用对象形式：
```json
"creep": {
  "behavior": "walk",
  "frames": [
    { "name": "creep1", "ms": 280 },
    { "name": "creep2", "ms": 200 },
    { "name": "creep3", "ms": 40 },
    { "name": "creep4", "ms": 40 }
  ],
  "loop": true
}
```

### 3.3 进右键菜单
动作加 `"menu": true` 即出现在右键动作列表。建议触发前让角色先站立（已在引擎内默认处理）。

### 3.4 动作序列（`next`）
非循环动作播完自动接续，可多目标按权重随机：
```json
"interact": {
  "behavior": "static",
  "frames": ["talk1", "talk2"],
  "loop": false,
  "next": [{ "id": "idle", "weight": 3 }, { "id": "sit", "weight": 1 }]
}
```
> 深度 > 8 自动截断，防止 `next` 互指造成死循环。

### 3.5 让动作自发出现（加权漫游）
在 `config/characters/<id>.json` 里配 `wanderActions`，空闲时按权重随机选：
```json
"wanderActions": [
  { "id": "walk", "weight": 5 },
  { "id": "sit", "weight": 2 },
  { "id": "sleep", "weight": 1 }
]
```
旧写法 `["walk", "sit"]` 仍兼容（等权重）。

### 3.6 同一动作的帧，画布尺寸要统一（否则鼠标和大小都会出问题）

角色的**鼠标命中框 = 当前帧 PNG 整块画布**（含四周透明留白）。所以同一个动作里画布尺寸不一致时：

- 命中框会**随帧忽大忽小** → 鼠标在角色旁边时，有时能点到桌面、有时点不动；
- 若该动作没配 `width/height`（也没给宽帧写 `scale: 1`），窄画布帧还会按比例缩放 → 角色**突然变大/变小**。

自查与修复（都在 `scripts/`，无需改代码）：

```bash
node scripts/diag-hitbox.mjs gwen          # 列出每个动作的 命中框 / 可见内容 / 左右死区
node scripts/verify-actions.mjs            # 结尾会「⚠ 告警」列出画布不统一的动作
node scripts/repad-frame.mjs --left n --right n --write <png...>   # 补透明边统一画布
```

`repad-frame.mjs` 只添加全透明像素、不动任何可见像素，并自校验「可见内容整体平移、逐字节一致」；
**左右等量补边（`--left n --right n`）时角色在屏幕上的位置零位移**，只把命中框撑到新画布宽度。

## 4. 何时「必须」改代码

只有一种情况需要动 `src/`：
> 你要的动作**不属于**上面 7 种 behavior，且 `trackMouse` / `windowMode` 也表达不了（例如「分裂出分身」「游泳」这类全新运动学）。

此时需改：
1. `src/renderer/types.ts` 的 `ActionBehavior` 联合类型（加一种）
2. `src/renderer/Pet.ts` 加一个 `stepXxx(dt, dtMs)` 步进函数，并在 `update()` 的 switch 里接上

加完重新 `npm run build-main && npm run build-renderer`。

---

## 5. 校验

改完跑：
```bash
npm run verify-actions
```
会逐动作检查：帧名是否都能对应到 PNG、manifest 是否合法、PNG 是否存在且有效。**0 失败**才算过关；
结尾若出现「⚠ 画布/显示尺寸不统一」告警，按 §3.6 补边处理（告警不阻塞，但会导致命中框跳变）。

## 6. 常见坑

| 现象 | 原因 | 解决 |
|---|---|---|
| 角色不出现 | id 没在 `config.json` 的 `characters` 登记 | 补登记一行 |
| 动作播出来是占位块/空白 | `frames` 里的帧名在 `images/<id>.json` 或 `assets/<id>/` 找不到 | 核对帧名拼写 / 补 PNG |
| 角色被压扁 | `size.height` 设太小 | 设成美术源图原始高度 |
| 倒挂帧（ceiling）贴地偏移 | 倒挂帧 anchor 不同 | 给该动作加 `offset: { "y": -N }` 补偿 |
| 右键「窗口」类动作点了没反应 | 非 Windows / koffi 未打包 | 仅 Windows 真机有效；便携版已内置 koffi |

---

## 7. 一句话流程回顾

**加角色** = 放 PNG → 写 `characters/<id>.json` → 写 `actions/<id>.json` → `config.json` 登记一行。
**加动作** = 往 `actions/<id>.json` 加一条（选 7 种 behavior 之一 + 帧 + 可选开关）。
**都不用碰源码**，除非要一种全新运动模式。
